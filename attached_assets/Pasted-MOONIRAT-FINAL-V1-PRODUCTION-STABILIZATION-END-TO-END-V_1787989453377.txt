MOONIRAT — FINAL V1 PRODUCTION STABILIZATION & END-TO-END VALIDATION

You are working on Moonirat, a creator-first music-video platform that serves BOTH creators/artists and viewers/fans.

Do NOT add new product features during this pass.

The goal is to make the existing V1 actually work end-to-end, securely, reliably, and ready for controlled public beta.

NON-NEGOTIABLE MOONIRAT VISION

Moonirat is NOT an artist-only platform.

It has two equally important experiences:

Viewer / Fan

Discover → Search → Watch → Like → Follow → Save → Return

Creator / Artist

Sign up → Create artist profile → Upload → Publish → Get discovered → Gain followers → View analytics

The product must support both journeys.

PHASE 4 — FIX SUPABASE AUTHORIZATION / 406 NOISE

The admin-role lookup currently produces unnecessary 406 behavior.

Fix the query correctly.

When checking whether the current user is an admin:
	•	Do not assume a row exists.
	•	Use nullable/safe single-row handling.
	•	“No admin role” must be treated as a normal authorization result, NOT an application error.
	•	Avoid .single() where zero rows are expected.
	•	Do not expose privileged information.
	•	Never put the Supabase service-role key in frontend code.
	•	Never bypass RLS from the browser.

Ensure:

Viewer without admin role → normal user experience.

Admin → admin functionality.

Unauthenticated user → authentication-required experience.

No role → no crash, no repeated 406 noise.
