VIEWER / FAN JOURNEY

Verify and fix:

1. Signed-out users see an appropriate feedback entry point.
2. Authenticated viewers can submit feedback.
3. Feedback types work:
    * Bug
    * Feature
    * Upload Issue
    * Playback Issue
    * Verification
    * Search/Discovery
    * General
4. Subject is required.
5. Message is required.
6. Input limits are enforced.
7. Submission is persisted to Supabase.
8. Successful submission produces a real success state.
9. User can open My Feedback.
10. User can see only their own feedback.
11. User can view current status.
12. User can view admin response/notes when appropriate.

CREATOR JOURNEY

Verify that creators/artists can:

1. Open feedback.
2. Submit creator-specific issues.
3. Report upload problems.
4. Report playback problems.
5. Report verification problems.
6. Submit feature requests.
7. See their submissions.
8. Track status changes.
9. Receive the appropriate status update through the existing notification/realtime system where already implemented.

Do not create a separate creator feedback system.

ADMIN JOURNEY

Verify that authorized admins can:

1. View feedback submissions.
2. Search feedback.
3. Filter by status.
4. Filter by type.
5. View priority.
6. Open the complete submission.
7. Add admin notes.
8. Change status:
    * open
    * reviewing
    * planned
    * resolved
    * closed
9. Save changes to Supabase.
10. Confirm the user can see the updated status.

All admin writes must be protected by real authorization.

Client-side checks alone are NOT sufficient.

RLS SECURITY

Test:

User A

Can:

* Create their own feedback.
* Read their own feedback.
* See updates to their own feedback.

Cannot:

* Read User B’s feedback.
* Modify User B’s feedback.
* Delete User B’s feedback.

Admin

Can:

* Read appropriate feedback.
* Update status.
* Add admin notes.

Unauthorized user

Cannot perform admin feedback actions.

Do not weaken existing RLS to make tests pass.

REALTIME

If the existing system uses Supabase Realtime:

Verify:

Admin changes status → User receives updated status without manually refreshing.

If Realtime is already correctly implemented, preserve it.

Do not introduce polling as a replacement.
